# نبض — نظام مراقبة الشبكة

نظام مراقبة شبكات متكامل: **ping دوري + SNMP** لراوترات وسويتشات MikroTik
وأجهزة Ubiquiti ونقاط الوصول، مع لوحة تحكم عربية ورسوم حركة بيانات، وتنبيهات
تيليجرام وبريد إلكتروني وWebhook، وسجل أحداث قابل للبحث والتصدير. صُمم ليعمل على جهاز داخل نفس شبكة الأجهزة المراقَبة
(Windows أو Linux) وبلا حدود على عدد الأجهزة أو المنافذ.

**المستودع:** <https://github.com/Mohammadzaza93/Nabd> — مرحّب بالمساهمات
والاقتراحات عبر Issues وPull Requests.

## المزايا

- فحص متوازٍ لكل الأجهزة كل عدد ثوانٍ قابل للضبط.
- **حد الفشل** (`fail_threshold`) لمنع الإنذارات الكاذبة عند فقدان حزمة واحدة.
- فهم **تبعية الأجهزة**: إذا سقط السويتش الأب تظهر الأجهزة التابعة له
  «لا يمكن الوصول» بدل إغراقك بعشرات إنذارات السقوط.
- كشف انقطاع الإنترنت من خلال فحص خوادم إنترنت متعددة، مع تمييزه عن سقوط الأجهزة.
- **مراقبة SNMP v2c احترافية** لراوترات وسويتشات MikroTik وأجهزة Ubiquiti:
  - حالة كل منفذ (يعمل/متوقف/معطّل) وسرعته، ومعدل الحركة الداخلة والخارجة لكل منفذ،
    مع الأخطاء والمهمَل، وإجمالي حركة الجهاز ورسم بياني تاريخي.
  - **SFP الضوئي**: قوة الاستقبال والإرسال (dBm)، الحرارة، الجهد، التيار، الطول
    الموجي، الماركة والرقم التسلسلي، وحالة فقد الاستقبال/خطأ الإرسال.
  - **اللاسلكي**: العملاء والراديوهات ونقاط الوصول مع قوة الإشارة والضجيج
    وSNR وسرعات الإرسال/الاستقبال وCCQ والتردد.
  - **CPU والذاكرة والحرارة** ومدة التشغيل واسم النظام وإصداره.
  - تنبيهات `port_down` (سقوط منفذ) و`high_cpu` (ارتفاع المعالج) و`sfp_low`
    (ضعف إشارة SFP) مع فترة تبريد تمنع تكرار التنبيه.
- **خمس عروض من شريط واحد**: 🖥 الأجهزة، 🗺 خريطة شبكة تفاعلية (سحب العقد وتكبير
  مع فلاتر بالحالة والمجموعة والبحث)، 📊 تقارير التوفر (SLA)، 🔔 مركز التنبيهات،
  و📜 سجل الأحداث (بحث وتصفية وتصدير CSV).
- **سجل قياسات تاريخي في SQLite** لكل جهاز (ping/CPU/الذاكرة/الحركة)، مع رسوم
  بيانية داخل التفاصيل، وتقارير توفر يومية/أسبوعية/شهرية قابلة للتصدير CSV.
- **مركز تنبيهات** يعرض المشاكل الحالية خطورةً ومدةً مع تأكيد فردي أو جماعي،
  و**وضع صيانة** يوقف الإشعارات مؤقتاً عن أي جهاز دون حذفه من المراقبة، وتُستبعد
  نوافذ الصيانة من حساب التوفر وزمن التوقف في التقارير (SLA).
- **سجل أحداث كامل**: سقوط/عودة الأجهزة، تعذّر الوصول، الأجهزة الجديدة، المنافذ،
  CPU، SFP، وبداية/نهاية الصيانة — مع بحث بالاسم/IP/النوع، فلاتر بالمدة والجهاز،
  وتصدير النتائج إلى CSV.
- **أعلى استهلاك للحركة الآن** مباشرة على لوحة الأجهزة من بيانات SNMP.
- **إشعارات بريد إلكتروني (SMTP)** و**Webhook** إلى جانب تيليجرام، مع أزرار رسائل
  تجريبية. يُرسل الـ Webhook JSON مع `X-Nabd-Event` وتوقيع `X-Nabd-Signature`
  (HMAC-SHA256) عند ضبط مفتاح سري، ويمكن اختيار أنواع الإشعارات المرسلة إليه.
- إشعارات تيليجرام مجمّعة (سقوط/رجوع/تقرير يومي) مع إعادة إرسال تلقائية عند عودة الشبكة.
- لوحة تحكم عربية: بحث، تصفية بالحالة والمجموعة، ترتيب، إيقاف مؤقت، وعدّادات مباشرة،
  ومؤشر SNMP بجانب كل جهاز يعرض CPU وحالة الاستجابة.
- إدارة كاملة من اللوحة: الأجهزة، الإعدادات، شبكات الفحص، الراوتر، تيليجرام،
  البريد، Webhook، SNMP، واختيار الإشعارات.
- **فحص الشبكة من اللوحة**: يفحص كل عنوان، يعرض ما استجاب ومنافذه، ويضيف ما تختاره للمراقبة.
- **تفاصيل كل جهاز** في نافذة بتبويبات: النظام، المنافذ، SFP، اللاسلكي، الحركة،
  مع فحص منافذ TCP وخدماتها عند الطلب.
- إضافة/تعديل/حذف الأجهزة من اللوحة مباشرة، مع التحقق من العناوين ومنع التكرار.
- إعداد تفاعلي `--setup` لإدخال عناوين الأجهزة والشبكات بنفسك دون قيم افتراضية.
- اكتشاف تلقائي للأجهزة من راوتر مايكروتك (ARP/DHCP/Bridge) أو بفحص الشبكة،
  مع التعرف على نوع الجهاز عبر SNMP عند توفره.
- قاعدة بيانات SQLite للأحداث مع تنظيف تلقائي للأحداث القديمة.
- حماية اختيارية للوحة بكلمة مرور (Basic Auth).
- **قاعدة بيانات مجانية مرنة**: SQLite بلا تثبيت، أو PostgreSQL مفتوح المصدر،
  مع نقل بياناتك من SQLite إلى PostgreSQL بضغطة زر من اللوحة.
- **نسخ احتياطية محلية مجانية بالكامل**: ضغط gzip + تحقق SHA-256 + تدوير
  يومي/أسبوعي/شهري + استعادة مع نسخة أمان، وكلها تُدار من عرض «🗄 البيانات».
- عميل SNMP داخلي خفيف بلا مكتبات خارجية (`snmp.py`).

## التشغيل السريع

1. ثبّت Python 3.9 أو أحدث (أثناء التثبيت فعّل **Add Python to PATH**)، واستنسخ المستودع:

   ```bat
   git clone https://github.com/Mohammadzaza93/Nabd.git
   cd Nabd
   copy config.example.yaml config.yaml
   copy devices.example.csv devices.csv
   ```

   > على Linux/Mac استبدل `copy` بـ `cp`. ويمكنك ترك `devices.csv` غير موجود
   > وإضافة الأجهزة من اللوحة مباشرة.

2. ثبّت المتطلبات:

   ```bat
   python -m pip install -r requirements.txt
   ```

3. شغّل الإعداد التفاعلي وأدخل عناوين أجهزتك بنفسك (اختياري — يمكنك إدخال كل شيء من اللوحة):

   ```bat
   python nabd.py --setup
   ```

   يسألك عن منفذ اللوحة وكلمة المرور، تيليجرام (اختياري)، شبكات الفحص،
   عنوان الراوتر، ثم أسماء وعناوين الأجهزة واحداً واحداً. لا توجد عناوين
   افتراضية — كل عنوان تكتبه أنت. ويمكنك لاحقاً إضافة/تعديل/حذف الأجهزة
   وضبط كل الإعدادات من اللوحة مباشرة.

4. شغّل:

   ```bat
   start-nabd.bat
   ```

   أو مباشرة: `python nabd.py`

5. افتح اللوحة: <http://localhost:8080>

> إذا كانت قائمة الأجهزة فارغة، تعمل اللوحة وتضيف أول جهاز من زر
> **＋ إضافة جهاز**. وإذا لم يوجد `config.yaml` إطلاقاً، يشغّل
> `start-nabd.bat` الإعداد التفاعلي مرة واحدة لإنشائه.

> **مهم:** يجب تشغيل نبض على جهاز متصل فعلياً بالشبكة التي فيها الأجهزة.
> تشغيله على شبكة أخرى سيجعل الأجهزة تظهر «لا يمكن الوصول إليها».

## إدخال العناوين وإدارة الأجهزة

طريقتان، وكلتاهما تحفظ في `devices.csv` مباشرة:

**1) من اللوحة (الأسهل):**
- زر **＋ إضافة جهاز**: الاسم، عنوان IP، النوع، المجموعة، والجهاز الأب.
- زر **تفاصيل** بجانب كل جهاز: حالته وتأخيره وآخر ظهور، وفحص منافذه وخدماته المفتوحة.
- زر **تعديل** بجانب كل جهاز لتغيير بياناته (بما فيها الاسم).
- زر **حذف** لإزالته من المراقبة.
- يتحقق نبض من صحة عنوان IP، ويرفض الأسماء أو العناوين المكررة، ويحدّث
  المراقبة فوراً دون إعادة تشغيل. وتُحدَّث تبعية الأجهزة تلقائياً عند إعادة
  تسمية جهاز أو حذفه.

**2) من الطرفية:** `python nabd.py --setup` لإدخال قائمة كاملة أو إضافة أجهزة،
أو تعديل `devices.csv` يدوياً. الأعمدة الأساسية: `name,ip,kind,parent,group`،
والاختيارية لـ SNMP: `snmp` (`auto`/`on`/`off`)، `snmp_community`
(مجتمع خاص بالجهاز)، `profile` (`auto`/`mikrotik`/`ubiquiti`/`generic`).

> تُنشأ نسخة احتياطية تلقائياً (`devices.csv.bak-...`) قبل أي إعادة كتابة من
> الإعداد التفاعلي. إدارة الأجهزة من اللوحة تحفظ الملف كتابةً آمنة (ملف مؤقت
> ثم استبدال) فلا يتلف عند الانقطاع.

## مراقبة SNMP (السويتشات والمنافذ وSFP واللاسلكي)

1. فعّل SNMP على الجهاز نفسه:
   - **MikroTik**: `IP → SNMP` ثم فعّل، واضبط Community (يُفضّل مجتمع قراءة فقط).
   - **Ubiquiti AirMAX**: `Services → SNMP` ثم فعّل وحدّد المجتمع.
2. من **⚙ الإعدادات → SNMP** اضبط المجتمع العام وفترة الاستعلام والمهلة وحدود
   التنبيه، ثم اضغط **اختبار SNMP** بعنوان جهاز للتأكد من الاستجابة.
3. من **＋ إضافة جهاز** أو **تعديل** اختر «مراقبة SNMP» (تلقائي/مفعّلة/متوقفة)
   ونوع SNMP (اكتشاف تلقائي أو MikroTik أو Ubiquiti أو عام)، ويمكن وضع مجتمع
   خاص بجهاز معيّن إن اختلف عن العام.
4. افتح **تفاصيل** أي جهاز لرؤية تبويبات: النظام (CPU/الذاكرة/الحرارة/المنافذ)،
   المنافذ (الحالة والسرعة والحركة والأخطاء)، SFP الضوئي، اللاسلكي، والحركة
   (رسم بياني للدخول والخروج). زر **⟳ استعلام SNMP الآن** يحدّث فوراً.

> الأجهزة التي لا تدعم SNMP تُترك على «تلقائي» فتُستعلم حسب نوعها؛ الأجهزة
> الخارجية (إنترنت/ISP/DVR/كاميرا) تُستثنى تلقائياً. الاستعلام الدوري لا يعطّل
> الواجهة، ويمكن إيقافه كلياً من الإعدادات.

## الإعدادات من اللوحة

زر **⚙ الإعدادات** يفتح كل ما يلزم دون تحرير ملفات:

- **المراقبة**: فترة الفحص، حد الفشل، عدد الفحوصات المتوازية، مدة الاحتفاظ
  بالأحداث، ساعة التقرير اليومي، وفترة تحديث اللوحة.
- **إشعارات البوت**: تشغيل/إيقاف كل نوع إشعار على حدة (سقوط/رجوع/إنترنت/جهاز
  جديد/تقرير يومي/سقوط منفذ/ارتفاع CPU/ضعف SFP).
- **تيليجرام**: توكن البوت و`chat_id` (يمكن جلب المعرّفات تلقائياً من رسائل
  البوت)، مع زر إرسال رسالة تجريبية.
- **SNMP**: التشغيل، المجتمع والمنفذ، فترة الاستعلام، المهلة والمحاولات،
  حد CPU، حد ضعف SFP، عدد نقاط الرسم، ومدة تبريد التنبيه، مع أزرار اختبار
  واستعلام فوري لكل الأجهزة.
- **السجل التاريخي والتقارير**: تفعيل حفظ القياسات، فترة العينة (افتراضي 60 ثانية)،
  ومدة الاحتفاظ (افتراضي 30 يوماً).
- **البريد الإلكتروني**: خادم SMTP والمنفذ والمستخدم وكلمة المرور والمرسل
  والمستلمون، مع STARTTLS أو SSL مباشر، وزر إرسال بريد تجريبي.
- **Webhook**: رابط الاستقبال، مفتاح التوقيع السري، وأنواع الإشعارات المرسلة،
  مع زر إرسال إشعار تجريبي (يعمل مع تيليجرام والبريد في الوقت نفسه).
- **فحص الشبكة**: شبكات الفحص وإعادة الفحص التلقائي الدوري.
- **الاكتشاف**: عنوان راوتر مايكروتك ومستخدم القراءة فقط وكلمة مروره ومنفذه.
- **اللوحة**: تعيين/تغيير كلمة المرور، والمنفذ (تغيير المنفذ يحتاج إعادة تشغيل).

كل التغييرات تُحفظ في `config.yaml` وتُطبَّق فوراً دون إعادة تشغيل (عدا تغيير
منفذ اللوحة). زر **🌐 الشبكة** يبدأ فحصاً فورياً لكل عناوين الشبكات، يعرض
المستجيب ومنافذه، ويتيح إضافة الأجهزة الجديدة بضغطة واحدة.

### شكل إشعار Webhook

```json
{
  "source": "nabd",
  "version": "2.5",
  "kind": "device_down",
  "title": "🔴 سقط جهاز: Router",
  "text": "نص الإشعار الكامل كما يظهر في تيليجرام",
  "timestamp": 1730000000.0,
  "time": "2026-11-20 12:00:00"
}
```

مع ترويسات `X-Nabd-Source: nabd` و`X-Nabd-Event: <kind>`، و`X-Nabd-Signature:
sha256=<hex>` عند ضبط مفتاح سري (HMAC-SHA256 على بايتات JSON المرسلة).

## مراقبة تفصيلية

- لكل جهاز: الحالة، التأخير، مدة الحالة، آخر ظهور، النوع، المجموعة، والجهاز الأب،
  ومؤشر SNMP (CPU% أو خطأ الاستجابة) بجانب الاسم.
- **شريط حالة SNMP** أعلى اللوحة يعرض عدد الأجهزة المستجيبة من إجمالي المراقَبة،
  وزرّاً للاستعلام الفوري عن كل الأجهزة بضغطة واحدة، بجانب زر 🔔 يعرض عدد
  التنبيهات غير المؤكدة.
- زر **تفاصيل** يفحص منافذ TCP الشائعة ويعرض الخدمة: SSH وTelnet وDNS وHTTP
  وHTTPS وSMB وRTSP وRDP وSNMP وHikvision وWinbox وRouterOS API والطابعات.
- فحص الشبكة يعرض كل عنوان مستجيب — حتى غير المضاف للمراقبة — مع اسم مقترح
  ونوع ومجموعة ومنافذ مفتوحة، ثم تضيفه بضغطة.
- بيانات SNMP (منافذ/SFP/لاسلكي/حركة) تُعرض في نافذة التفاصيل وتُحدَّث تلقائياً
  أثناء فتحها، وتبويب **الحركة** يعرض رسوماً من الذاكرة ومن السجل التاريخي
  باختيار المدة (ساعة إلى 30 يوماً).
- **🗺 الخريطة**: أجهزة مرتبة حسب `parent` بألوان الحالة، تحريك العقد وحفظ
  مواضعها محلياً، تكبير/تصغير وتنقل بالفأرة، وضغطة على أي عقدة تفتح تفاصيلها،
  مع فلاتر بالحالة (بما فيها المشاكل والصيانة) والمجموعة والبحث بالاسم/IP.
- **📊 التقارير**: توفر كل جهاز ونسبة الانقطاعات وزمن التوقف ومتوسط التأخير
  وCPU والذاكرة وذروة الحركة، مع خريطة حرارية لآخر 30 يوماً وتصدير CSV.
- **🔔 التنبيهات**: سقوط جهاز، تعذّر الوصول، ارتفاع CPU، منافذ متوقفة، وضعف
  SFP — مع تأكيد، فتح تفاصيل، ووضع صيانة من نفس الشاشة أو من نافذة الجهاز.
- **📜 السجل**: كل الأحداث السابقة مع وقت الحدث ومنذ كم وقت، فلاتر (النوع،
  الجهاز، المدة 24 ساعة/7 أيام/30 يوماً/الكل، البحث)، عدّادات سريعة، وتصدير CSV.

## واجهات API المستخدمة من اللوحة

| الواجهة | الوظيفة |
| --- | --- |
| `GET /api/status` | الحالة المباشرة للأجهزة والشبكة وSNMP والتنبيهات وآخر الأحداث |
| `GET /api/metrics/<name>?range=1h` | سلسلة قياسات جهاز للرسوم البيانية |
| `GET /api/reports?range=24h` / `GET /api/reports/export` | تقرير التوفر وتصديره (مع استبعاد الصيانة) |
| `GET /api/alerts` / `POST /api/alerts/ack` | التنبيهات النشطة وتأكيدها |
| `POST /api/devices/<name>/maintenance` | تفعيل/إيقاف وضع الصيانة وتسجيل نافذته الزمنية |
| `GET /api/events?q=&type=&name=&range=&limit=` | سجل الأحداث مع الفلاتر |
| `GET /api/events/export?...` | تصدير السجل المُصفّى إلى CSV |
| `POST /api/webhook/test` | إرسال إشعار Webhook تجريبي (يقبل `url` و`secret` اختيارياً لاختبار الإعداد قبل حفظه) |

> ملاحظة: كل واجهات `POST/PUT` تتطلب `Content-Type: application/json`،
> وإذا عُيّنت كلمة مرور للوحة فستُطلب Basic Auth كما في بقية اللوحة.

## الأوامر

| الأمر | الوظيفة |
| --- | --- |
| `python nabd.py` | تشغيل المراقبة واللوحة |
| `python nabd.py --setup` | إعداد تفاعلي: إدخال عناوين الأجهزة والشبكات وكلمة المرور |
| `python nabd.py --check` | فحص الإعدادات وقاعدة البيانات والراوتر والإنترنت |
| `python nabd.py --test` | إرسال رسالة تجريبية إلى تيليجرام |
| `python nabd.py --chat-id` | معرفة `chat_id` بعد إرسال رسالة للبوت |
| `python nabd.py --discover` | اكتشاف الأجهزة من راوتر مايكروتك وإضافتها إلى CSV |
| `python nabd.py --scan` | فحص الشبكات في `scan.subnets` وإضافة الأجهزة المكتشفة |

## أنواع الأجهزة (`kind`)

- `router` / `switch` / `dvr` / `camera` / `wifi` / `server` / `isp`: جهاز عادي.
- `internet`: عناوين إنترنت عامة (مثل `8.8.8.8` و`1.1.1.1`) تُستخدم لتحديد حالة الإنترنت.
- `isp`: بوابة مزود الخدمة (اختياري، تظهر في رسالة انقطاع الإنترنت).
- `group`: أي نص لتصنيف الأجهزة في اللوحة.
- `parent`: اسم جهاز آخر (مثل السويتش الأب) لبناء شجرة التبعية.

## حل المشكلات

| المشكلة | الحل |
| --- | --- |
| كل الأجهزة «متوقفة» | تأكد أن نبض يعمل على جهاز داخل نفس الشبكة، وأن جدار الحماية يسمح بـ ICMP |
| اللوحة لا تُفتح من جهاز آخر | اسمح للمنفذ 8080 في جدار حماية Windows |
| لا تصل إشعارات تيليجرام | من **⚙ الإعدادات** أضف التوكن وchat_id ثم أرسل رسالة تجريبية |
| الأجهزة تظهر «لا يمكن الوصول» | جهاز أعلى في `parent` متوقف؛ تحقق منه أولاً |
| جهاز يعمل لكن يظهر متوقفاً | بعض الأجهزة تحجب ping؛ افتح **تفاصيل** وافحص منافذه |
| SNMP لا يستجيب | تأكد من تفعيل SNMP على الجهاز، صحة المجتمع/المنفذ، وأن جدار الحماية يسمح بـ UDP 161 |
| لا تظهر المنافذ أو SFP | قد يكون الجهاز لا يدعم الجداول؛ جرّب نوع SNMP المناسب أو «عام»، وتأكد من تفعيل SNMP على السويتش |
| لا تصل رسائل البريد | من **الإعدادات** اضبط خادم SMTP والمرسل والمستلم واضغط «بريد تجريبي»، وتأكد من المنفذ وTLS/SSL |
| لا يصل Webhook | تأكد أن الرابط http/https وأن نوع الحدث مسموح في `webhook.kinds`، ثم جرّب «إرسال إشعار تجريبي»؛ راجع `nabd.err.log` |
| سجل الأحداث فارغ | تأكد من المدة المختارة (أو اختر «الكل») ومن أن قاعدة البيانات `nabd.db` موجودة وقابلة للكتابة |
| خطأ `No module named flask` | `python -m pip install -r requirements.txt` |

## قاعدة البيانات والنسخ الاحتياطي

نبض يدعم محركين، كلاهما مجاني تماماً:

| المحرك | متى تختاره | التثبيت |
| --- | --- | --- |
| `sqlite` (افتراضي) | جهاز واحد، تثبيت بسيط بلا خدمة | لا شيء — ملف `nabd.db` |
| `postgres` | خادم، عدة مستخدمين، حجم كبير | PostgreSQL مفتوح المصدر (GPL) |

### التحويل إلى PostgreSQL

1. ثبّت PostgreSQL (من `postgresql.org` أو مدير الحزم). يمكن أيضاً استخدام
   **الأرشيف الرسمي المحمول** من EnterpriseDB دون صلاحيات admin، ثم ضبط
   `database.postgres.bin_dir` على مجلد `bin` الذي يحوي `pg_dump` و`psql`.
2. أنشئ قاعدة ومستخدم للقراءة/الكتابة:
   ```sql
   CREATE USER nabd WITH PASSWORD 'كلمة-قوية';
   CREATE DATABASE nabd OWNER nabd;
   ```
3. من لوحة نبض → **🗄 البيانات** اختر `postgres`، املأ المضيف/المنفذ/القاعدة/
   المستخدم/كلمة المرور، واحفظ. ثم أعد تشغيل نبض.
4. اضغط **⇪ استيراد من SQLite** لنقل الأحداث والقياسات ونوافذ الصيانة دفعة واحدة
   (يتم مرة واحدة فقط ويُمنع تكرارها).

### النسخ الاحتياطية (محلية ومجانية 100%)

- تُؤخذ نسخة متسقة أثناء الكتابة: `sqlite3.backup()` أو `pg_dump` الرسمي.
- تُضغط بصيغة `gzip` ويُكتب ملف `.sha256` لكل نسخة للتحقق من سلامتها.
- **تدوير تلقائي**: أحدث نسخة كل ساعة/يوم، ثم نسخ أسبوعية وشهرية حسب
  `keep_daily` / `keep_weekly` / `keep_monthly`. القديم يُحذف تلقائياً.
- نسخة تلقائية كل `interval_hours` ساعة، و زر **＋ نسخة الآن** عند الطلب.
- **الاستعادة** تنشئ نسخة أمان قبل أي تغيير، ثم تستعيد النسخة المختارة.
- المجلد الافتراضي `backups/` مستبعد من Git، ويمكن تغييره إلى أي مسار
  (مثل USB أو مشاركة شبكية) من اللوحة — دون أي خدمة مدفوعة.

### واجهات قاعدة البيانات

| الواجهة | الوظيفة |
| --- | --- |
| `GET /api/db/status` | المحرك، الاتصال، الحجم، عدد الصفوف، عدد النسخ |
| `GET /api/db/backups` | قائمة النسخ مع الحجم والتحقق |
| `POST /api/db/backup` | إنشاء نسخة الآن |
| `POST /api/db/settings` | حفظ إعدادات المحرك/النسخ |

| `GET /api/db/backups/<name>/download` | تنزيل نسخة |
| `DELETE /api/db/backups/<name>` | حذف نسخة |
| `POST /api/db/backups/<name>/restore` | استعادة نسخة |

## الأمان

- `config.yaml` قد يحتوي على توكن البوت وكلمة مرور الراوتر ومفتاح Webhook — لا تشاركه.
- إذا تسرّب التوكن، أبطله من BotFather وأنشئ آخر، ثم ضعه في
  `NABD_TELEGRAM_TOKEN` أو عبر `--setup` (لا تكتبه في ملف تشاركه).
- **عيّن `dashboard.password` دائماً** إذا كانت اللوحة متاحة على الشبكة؛
  فبدونها يستطيع أي جهاز على الشبكة عرض الأجهزة وإضافة/تعديل/حذف العناوين.
  يمكن وضع كلمة المرور في `NABD_DASH_PASSWORD` بدل الملف.
- لوحة التحكم تستخدم HTTP عادي؛ استخدمها داخل الشبكة الداخلية فقط، أو ضعها خلف
  وكيل HTTPS (مثل Caddy أو IIS) وكلمة مرور قوية.
- يُنصح بإنشاء مستخدم **قراءة فقط** على الراوتر للاكتشاف.
